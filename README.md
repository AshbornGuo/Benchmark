# REMBbenchmark

REMBbenchmark is an open-source benchmark suite for evaluating and comparing optimisation algorithms on real-life expensive multi-objective black-box optimisation problems. The benchmark suit contains:

- three benchmark problems including a continuous simulation-based problem `LayeredBeam`, a mixed discrete and continuous architecture optimisation problem `Turbofan`, and a high-dimensional surrogate-based problem `Mazda`.

  | Problem | Obj. | Var. | Constr. | Type |
  |---------|------|------:|---------:|------|
  | LayeredBeam | 2 | 10 | 0 | Continuous |
  | Turbofan | 3 | 41 | 15 | Mixed |
  | Mazda | 2 | 222 | 54 | Discrete |

- several optimisation algorithms including surrogate-based optimisation methods(qLogNEHVI, qLogNParEGO, MESMO), evolutionary algorithms(NSGA-II, MOEA/D, SMS-EMOA), a hybrid method (EGBO) and a baseline (Random search).

  | Category | Algorithm | Framework |
  |----------|-----------|------------|
  | SBO | qLogNEHVI | BoTorch |
  | SBO | qLogNParEGO | BoTorch |
  | SBO | MESMO | BoTorch |
  | EA | NSGA-II | pymoo |
  | EA | SMS-EMOA | pymoo |
  | EA | MOEA/D | pymoo |
  | Hybrid | EGBO | BoTorch |
  | Baseline | Random Search | - |

- experement results, which benchmark above algorithms on these three bechmark problems.  


## Repository structure

- `problem_sets`  
  Contains the three benchmark problems collected and integrated from external benchmark suites.

- `results`  
  Stores experimental results grouped by benchmark problem, with each problem directory containing the outputs of different algorithms.

- `suite`  
  Contains the implementation of optimisation algorithms organised by benchmark problem. Each benchmark problem directory includes the execution scripts and analysis scripts for different algorithms.

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/AshbornGuo/REMBbenchmark.git
cd REMBenchmark
```

### 2. Create environment

```bash
conda create -n rembenchmark python=3.11
conda activate rembenchmark
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Mazda benchmark setup
- To use the Mazda CdMOBP benchmark, please obtain the original benchmark package from: https://ladse.eng.isas.jaxa.jp/benchmark/

The original package contains:

- Mazda_CdMOBP/Info_Mazda_CdMOBP.xlsx
- Mazda_CdMOBP/Info_test.xlsx
- Mazda_CdMOBP/Mazda_CdMOBP/bin/Win64/mazda_mop.exe

After downloading the benchmark, copy these files into the locations specified in `problem_sets/mazda_interface`.

This repository does not redistribute any files from the original Mazda CdMOBP benchmark package.

### 5. LayeredBeam benchmark setup
- To use the LayeredBeam benchmark from MECHBench, please download [OpenRadioss](https://openradioss.org/) from the official website and extract it to a suitable local directory on your machine. Then update the OpenRadioss installation path in the corresponding script (e.g. `LB_RandomSearch.py`):

```python
orss_main_path = "/your/path/to/OpenRadioss/"
```

## How to use this suite

### 1. Quick Start

Run the qLogNParEGO algorithm on the Turbofan benchmark:

```bash
cd suite/experiments/TurbofanArch
python TurbofanArch_ParEGO.py
```

The generated results will be stored in the corresponding results directory.

### 2. Explore Benchmark Results

- Experimental results are available in the `results` directory. For example, the results generated by `NSGA-II` on the `Mazda` benchmark problem can be found in: `results/mazda/NSGA2`


### 3. Reproduce Existing Experiments

- Each benchmark directory in `suite` contains the implementations of the optimisation algorithms used in the benchmark study. For example, to reproduce the qLogNParEGO results on the Turbofan benchmark:

```bash
cd suite/experiments/TurbofanArch
python TurbofanArch_EGBO.py
```

### 4. Benchmark Your Own Algorithms
- The benchmark problems are provided in the `problem_sets` directory. Users may implement their own optimisation algorithms and evaluate them on the provided benchmark problems (LayeredBeam, Turbofan, and Mazda).


### 5. Adapt the Framework to New Problems

- The framework can be extended to incorporate additional optimisation benchmark problems. The existing code structure may serve as a template for integrating new benchmark problems and evaluating optimisation algorithms in a consistent manner.
